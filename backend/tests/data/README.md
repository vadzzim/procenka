# Тестовые данные

## `control_cases.csv`

Контрольные примеры расчёта цены (раздел «Сверка» в `plan.md`). Одна строка — один расчёт: входные данные и вручную рассчитанный ожидаемый результат. Ожидаемые значения не генерируются кодом.

Тест: `tests/unit/pricing/test_control_cases.py`. После прогона pytest печатает итог `control cases: N matched, M mismatched`; при расхождении тест показывает входные данные строки, ожидаемое и фактическое.

Разделитель — запятая, кодировка UTF-8. Деньги и проценты — десятичные числа с точкой, без пробелов.

| Колонка | Смысл |
|---|---|
| `id` | идентификатор строки, он же id теста |
| `description` | что проверяет строка |
| `brand`, `article` | бренд и артикул товара в исходном виде |
| `purchase` | закупка, ₽ |
| `markup_percent` | минимальная наценка на закупку в процентах (`20` = 20 %) |
| `step` | шаг ниже конкурента, ₽ |
| `ceiling` | потолок, ₽; пусто — потолка нет |
| `published` | текущая опубликованная цена, ₽; пусто — её нет |
| `threshold_percent` | порог карантина в процентах |
| `offers` | предложения через `;`, каждое `brand\|article\|price\|stock\|delivery_days`; пусто — предложений нет |
| `expected_price` | ожидаемая рекомендация, ₽ с копейками; пусто — рекомендации нет |
| `expected_state` | `published`, `unchanged`, `quarantine` или `retained` |
| `expected_reason` | код причины состояния (`price_spike`, `no_previous_price`, `no_eligible_offers`, `invalid_purchase_price`, `rules_conflict`); пусто — причины нет |
| `expected_rejected` | коды причин отброшенных предложений через `;` в порядке предложений; пусто — ничего не отброшено |

Общие настройки во всех строках по умолчанию: коэффициент подозрительно низкой цены 0,5, максимальный срок поставки 14 дней.
